## 부하 테스트란?

부하 테스트는 **시스템이 동시에 여러 요청을 처리할 수 있는지** 확인하는 테스트입니다.

### 왜 필요한가?

- **실전 준비**: 100명이 동시에 QR을 스캔할 때 서버가 제대로 작동하는지 확인
- **성능 측정**: 응답 시간이 얼마나 걸리는지 확인
- **문제 발견**: 동시 접속 시 발생할 수 있는 오류를 미리 발견

### 테스트할 시나리오

1. **추첨번호 발급** (`lottery`): 100명이 동시에 현장 QR을 스캔하여 추첨번호 발급
2. **부스 QR 스캔** (`booth`): 100명이 동시에 부스 QR을 스캔
3. **인증** (`auth`): 100명이 동시에 로그인 시도

## 현재 스크립트의 작동 방식

### 1. 초기화 단계

```javascript
// 명령줄 인자 파싱
const CONCURRENT_USERS = 100; // 동시 사용자 수
const ENDPOINT = "lottery"; // 테스트할 엔드포인트
const BASE_URL = "http://localhost:3000"; // 서버 URL
```

### 2. 테스트 사용자 생성

```javascript
// 각 사용자마다 랜덤한 직원번호와 토큰 생성
function generateTestUser() {
  const empno = `TEST${랜덤숫자}`;
  const tokenSecret = 랜덤문자열;
  return { empno, tokenSecret };
}
```

### 3. 동시 요청 생성

```javascript
// 100명의 사용자를 생성하고 동시에 요청 보내기
const users = Array.from({ length: 100 }, () => generateTestUser());
const promises = users.map((user, index) => testFunction(user, index));

// 모든 요청이 완료될 때까지 대기
await Promise.allSettled(promises);
```

### 4. 통계 수집

각 요청마다 다음 정보를 수집:

- **성공/실패 여부**
- **응답 시간** (요청 시작부터 응답 받을 때까지)
- **오류 메시지**

### 5. 결과 출력

- 총 요청 수, 성공률, 실패률
- 응답 시간 통계 (평균, 최소, 최대, P50, P95, P99)
- 주요 오류 유형

```bash

```

실제로 작동하는 테스트를 위해서는:

- 테스트 사용자들이 데이터베이스에 존재해야 함
- 또는 관리자 페이지에서 테스트 사용자 생성

## 실행 방법

### 기본 실행

```bash
# 기본 설정으로 실행 (100명, 추첨번호 발급 테스트)
node test/load-test.js
```

### 옵션 지정 실행

#### 1. 사용자 수 변경

```bash
# 50명으로 테스트
node test/load-test.js --users=50

# 200명으로 테스트
node test/load-test.js --users=200
```

#### 2. 엔드포인트 변경

```bash
# 부스 QR 스캔 테스트
node test/load-test.js --endpoint=booth

# 인증 테스트
node test/load-test.js --endpoint=auth
```

#### 3. 서버 URL 변경

```bash
# 다른 서버에서 테스트
node test/load-test.js --base-url=http://192.168.1.100:3000

# 프로덕션 서버 테스트 (주의!)
node test/load-test.js --base-url=https://your-production-server.com
```

#### 4. 여러 옵션 조합

```bash
# 150명, 부스 스캔, 다른 서버
node test/load-test.js --users=150 --endpoint=booth --base-url=http://192.168.1.100:3000
```

## 결과 해석

### 예시 출력

```
============================================================
부하 테스트 시작
============================================================
동시 사용자 수: 100
테스트 엔드포인트: lottery
서버 URL: http://localhost:3000
============================================================

진행 상황: 100/100 (100.0%) - 성공: 95, 실패: 5

============================================================
부하 테스트 결과
============================================================
총 요청 수: 100
성공: 95 (95.00%)
실패: 5 (5.00%)
총 소요 시간: 3.45초

응답 시간 통계:
  평균: 234.56ms
  최소: 45ms
  최대: 1234ms
  중간값 (P50): 189ms
  P95: 567ms
  P99: 890ms

주요 오류:
  Request failed with status code 401: 5회
============================================================
```

### 지표 설명

#### 1. 성공률

- **95% 이상**: ✅ 정상 (실전 운영 가능)
- **90-95%**: ⚠️ 주의 (일부 개선 필요)
- **90% 미만**: ❌ 문제 (심각한 개선 필요)

#### 2. 응답 시간

- **평균**: 모든 요청의 평균 응답 시간
- **최소/최대**: 가장 빠른/느린 응답 시간
- **P50 (중간값)**: 50%의 요청이 이 시간 이내에 완료
- **P95**: 95%의 요청이 이 시간 이내에 완료
- **P99**: 99%의 요청이 이 시간 이내에 완료

**좋은 응답 시간 기준:**

- 평균 < 500ms: ✅ 매우 좋음
- 평균 < 1000ms: ✅ 좋음
- 평균 < 2000ms: ⚠️ 보통
- 평균 > 2000ms: ❌ 느림

#### 3. 오류 분석

- **401 Unauthorized**: 인증 실패 (토큰 문제)
- **500 Internal Server Error**: 서버 오류
- **Timeout**: 요청 시간 초과
- **Network Error**: 네트워크 연결 실패

## 개선된 부하 테스트 (권장)

현재 `load-test.js` 스크립트는 **테스트 토큰**을 사용하기 때문에 실제로는 인증 오류가 발생할 수 있습니다.

### 실제 작동하는 부하 테스트: `load-test-real.js`

더 정확한 테스트를 위해 **실제 인증된 사용자**를 사용하는 개선된 스크립트를 제공합니다.

#### 주요 차이점

| 기능        | load-test.js            | load-test-real.js |
| ----------- | ----------------------- | ----------------- |
| 인증        | 테스트 토큰 (실패 가능) | 실제 사용자 인증  |
| 사용자 생성 | 수동 필요               | 자동 생성         |
| 정확도      | 낮음                    | 높음              |
| 실행 시간   | 빠름                    | 느림 (인증 포함)  |

#### 사용 방법

```bash
# 기본 실행 (100명, 추첨번호 발급, 자동 생성 및 정리)
node test/load-test-real.js

# 사용자 생성 없이 실행 (이미 생성된 사용자 사용)
node test/load-test-real.js --create-users=false

# 테스트 후 정리
node test/load-test-real.js --cleanup=true

# 부스 스캔 테스트
node test/load-test-real.js --endpoint=booth
```

#### 실행 프로세스

1. **테스트 사용자 생성** (자동)

   - 관리자 API를 통해 테스트 사용자 생성
   - LOTTERY_TEST001 ~ LOTTERY_TEST100 형식

2. **사용자 인증** (배치 처리)

   - 10명씩 배치로 인증하여 서버 부하 방지
   - 각 사용자마다 실제 토큰 획득

3. **부하 테스트 실행**

   - 인증된 사용자들로 동시 요청
   - 실제 API 호출

4. **결과 분석**

   - 성공률, 응답 시간 통계
   - 오류 분석

5. **정리** (선택사항)
   - 테스트 사용자 삭제

#### 단계별 테스트 권장

```bash
# 1단계: 소규모 테스트 (10명)
node test/load-test-real.js --users=10

# 2단계: 중규모 테스트 (50명)
node test/load-test-real.js --users=50

# 3단계: 대규모 테스트 (100명)
node test/load-test-real.js --users=100
```

#### 모니터링과 함께 실행

부하 테스트 실행 중:

1. 관리자 페이지에서 `/api/admin/monitor` 확인
2. 서버 리소스 사용량 확인 (CPU, 메모리)
3. 데이터베이스 성능 확인

## 주의사항

1. **프로덕션 서버 테스트 주의**

   - 프로덕션 서버에 부하 테스트를 실행하면 실제 사용자에게 영향을 줄 수 있습니다
   - 반드시 테스트 환경에서만 실행하세요

2. **데이터베이스 부하**

   - 많은 동시 요청은 데이터베이스에 부하를 줍니다
   - 테스트 후 불필요한 테스트 데이터는 정리하세요

3. **서버 리소스**
   - 부하 테스트는 서버의 CPU와 메모리를 많이 사용합니다
   - 테스트 중 다른 작업은 피하세요

## 문제 해결

### Q: 모든 요청이 401 오류로 실패합니다

**A**: 테스트 토큰이 유효하지 않습니다. 실제 인증된 사용자를 사용하는 개선된 스크립트가 필요합니다.

### Q: 응답 시간이 너무 깁니다

**A**:

- 서버 리소스 확인 (CPU, 메모리)
- 데이터베이스 성능 확인
- 네트워크 지연 확인

### Q: 일부 요청만 실패합니다

**A**:

- 동시성 문제일 수 있습니다 (이미 수정됨)
- 서버 로그 확인
- 특정 오류 패턴 확인
